= SANtricity System Managerでの自動プール作成と手動プール作成について説明します
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
プールを自動または手動で作成して物理ストレージをグループ化し、必要に応じて動的に割り当てることができます。プールの作成時には、物理ドライブを追加できます。



== 自動作成

System Managerがストレージ アレイ内で未割り当て容量を検出すると、プールの自動作成が開始されます。未割り当て容量が検出された場合は、プールを作成するか、または未割り当て容量を既存のプールに追加するか（あるいはその両方を行うか）を確認するメッセージがSystem Managerによって自動的に表示されます。

プールの自動作成は、次のいずれかの条件に該当する場合に行われます。

* ストレージアレイ内にプールは存在せず、新しいプールを作成するのに十分な数の類似ドライブが存在します。
* 少なくとも1つのプールを含むストレージ アレイに新しいドライブが追加される。


プール内の各ドライブは、タイプ（HDDまたはSSD）が同じであり、同等の容量を備えている必要があります。次のタスクを実行するよう求めるメッセージがSystem Managerに表示されます。

* 同じタイプの十分な数のドライブがある場合は、1つのプールを作成する。
* 未割り当て容量が異なるドライブ タイプのドライブで構成されている場合は、複数のプールを作成する。
* ストレージアレイに既にプールが定義されている場合は、ドライブを既存のプールに追加し、同じドライブタイプの新しいドライブをプールに追加します。
* タイプの異なる複数のドライブを追加した場合は、ドライブ タイプが同じドライブを既存のプールに追加し、別のドライブ タイプのドライブを使用して別のプールを作成する。




== 手動作成

自動作成では最適な構成を判断できない場合は、プールを手動で作成することをお勧めします。このような状況は、以下のいずれかの理由で発生する可能性があります：

* 新しいドライブが複数のプールに追加される可能性がある。
* 新たに選定されたプール候補のうち1つ以上は、シェルフ損失の保護またはドロワー損失の保護を利用できます。
* 1つ以上の現在のプールの候補で、シェルフ損失の保護またはドロワー損失の保護のステータスを維持できない。


ストレージアレイ上に複数のアプリケーションがあり、それらが同じドライブリソースを競合しないようにしたい場合は、手動でプールを作成することもできます。この場合、1つまたは複数のアプリケーション用に、より小さなプールを手動で作成することを検討してもよいでしょう。ワークロードを、データを分散させるための多数のボリュームを持つ大規模なプールに割り当てる代わりに、1つまたは2つのボリュームだけを割り当てることができます。特定のアプリケーションのワークロード専用のプールを手動で作成することで、ストレージアレイの操作をより迅速に、競合を少なく実行できるようになります。
