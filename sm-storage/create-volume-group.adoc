= SANtricity System Managerでボリュームグループを作成します
:allow-uri-read: 
:experimental: 
:icons: font
:imagesdir: ../media/


[role="lead"]
ボリュームグループを使用すると、ホストからアクセス可能な1つ以上のボリュームを作成できます。ボリュームグループとは、RAIDレベルや容量など、共通の特性を持つボリュームを格納するコンテナのことです。

大容量のドライブとボリュームをコントローラ間で分散させる機能を利用して、1つのボリューム グループに複数のボリュームを作成すると、ストレージ容量を効率的に使用してデータを適切に保護するのに役立ちます。

.開始する前に
ボリューム グループを作成する前に、次のガイドラインを確認してください。

* 未割り当てのドライブが少なくとも1本必要です。
* 1つのボリューム グループに含めることができるドライブ数には制限があります。制限はRAIDレベルによって異なります。
* シェルフ / ドロワー損失の保護を有効にするには、少なくとも3台（RAID 1を使用する場合は2台）のシェルフまたはドロワーに配置されたドライブを使用するボリューム グループを作成する必要があります。
* EF600またはEF300ストレージ アレイを使用していて、ボリューム グループを手動で作成する場合は、各コントローラが最初の12個のスロットと最後の12個のスロットそれぞれで同じ数のドライブにアクセスできるようにします。この構成により、コントローラがドライブ側の両方のPCIeバスをより効果的に使用できるようになります。現在、System Managerでは、ボリューム グループの作成時にドライブを選択するには、[アドバンスト]機能を使用します。
* ボリューム グループの容量は、選択するRAIDレベルによって次のように異なります。
+
** RAID 1を選択する場合は、ミラーリングされたペアが選択されるように、一度に2台のドライブを追加する必要があります。ミラーリングとストライピング（RAID 10またはRAID 1+0として知られる）は、4台以上のドライブを選択した場合に実現されます。
** RAID 5を使用する場合は、少なくとも3本のドライブを追加してボリューム グループを作成する必要があります。
** RAID 6を使用する場合は、少なくとも5本のドライブを追加してボリューム グループを作成する必要があります。




.手順
. メニュー：Storage[Pools & Volume Groups]を選択します。
. メニュー：Create[Volume group]をクリックします。
+
[ボリューム グループの作成]ダイアログ ボックスが表示されます。

. ボリューム グループの名前を入力します。
. データ ストレージと保護の要件に応じて最適なRAIDレベルを選択します。
+
ボリューム グループ候補の表に、選択したRAIDレベルをサポートする候補だけが表示されます。

. *オプション：* ストレージアレイに複数の種類のドライブがある場合は、使用するドライブの種類を選択してください。
+
ボリューム グループ候補の表に、選択したドライブ タイプとRAIDレベルをサポートする候補だけが表示されます。

. *オプション：*ボリュームグループで使用するドライブを定義するために、自動方式または手動方式のいずれかを選択できます。自動方式がデフォルトの選択肢です。
+
ドライブを手動で選択するには、*ドライブを手動で選択する（詳細）*リンクをクリックしてください。クリックすると、*ドライブを自動的に選択する（詳細設定）*に変わります。

+
手動方式では、特定のドライブを選択してボリューム グループを構成できます。未割り当ての特定のドライブを選択して必要な容量を確保することができます。ストレージ アレイにメディア タイプやインターフェイス タイプが異なるドライブが混在している場合、新しいボリューム グループの作成用に選択できるのは1つのドライブ タイプの未設定の容量のみです。

+
[NOTE]
====
ドライブの冗長性と最適なドライブ構成を理解している専門家のみが、Manual方式を使用すべきです。

====
. 表示されたドライブの特性に基づいて、ボリュームグループで使用するドライブを選択し、*作成*をクリックします。
+
表示されるドライブ特性は、自動方式と手動方式のどちらを選択したかによって異なります。

+
.自動方式のドライブ特性
[%collapsible]
====
[cols="25h,~"]
|===
| 特性 | 使用 


 a| 
空き容量
 a| 
使用可能な容量（GiB）を示します。アプリケーションのストレージ ニーズに応じて、必要な容量のボリューム グループ候補を選択します。



 a| 
合計ドライブ数
 a| 
このボリューム グループに含まれるドライブの数を示します。必要なドライブ数のボリューム グループ候補を選択します。



 a| 
ドライブ ブロック サイズ（EF300およびEF600のみ）
 a| 
グループ内のドライブが書き込めるブロック サイズ（セクター サイズ）を示します。値は次のとおりです。

** 512 - 512バイト セクター サイズ。
** 4K -- 4,096 バイトのセクターサイズ。




 a| 
セキュリティ対応
 a| 
このボリュームグループ候補が、セキュリティ対応ドライブ（Full Disk Encryption（FDE）ドライブまたはFederal Information Processing Standard（FIPS）ドライブのいずれか）のみで構成されているかどうかを示します。

** ドライブセキュリティを使用してボリュームグループを保護できますが、この機能を使用するには、すべてのドライブがセキュア対応である必要があります。
** FDE専用のボリュームグループを作成する場合は、「セキュア対応」列で*はい - FDE*を探してください。FIPS専用のボリュームグループを作成する場合は、*はい - FIPS*または*はい - FIPS（混合）*を探してください。「混合」とは、140-2レベルと140-3レベルのドライブが混在していることを示します。これらのレベルを組み合わせて使用する場合、ボリュームグループはより低いセキュリティレベル（140-2）で動作することに注意してください。
** セキュリティ機能を備えているか否かにかかわらず、あるいはセキュリティレベルが異なるドライブが混在するボリュームグループを作成できます。ボリュームグループ内のドライブにセキュリティ機能に対応していないドライブが含まれている場合、ボリュームグループをセキュリティで保護することはできません。




 a| 
セキュリティを有効化
 a| 
セキュリティ対応ドライブでドライブセキュリティ機能を有効にするオプションを提供します。ボリュームグループがセキュリティ対応で、セキュリティキーを設定している場合は、チェックボックスをオンにしてドライブセキュリティを有効にできます。


NOTE: ドライブセキュリティを有効にした後でそれを解除する唯一の方法は、ボリュームグループを削除してドライブを消去することです。



 a| 
DA 対応
 a| 
このグループに対してデータアシュアランス（DA）が利用可能かどうかを示します。データアシュアランス（DA）は、コントローラからドライブへデータが転送される際に発生する可能性のあるエラーをチェックし、修正します。

DAを使用する場合は、DA対応のボリュームグループを選択してください。（DA対応ドライブの場合、プール内に作成されたボリュームではDAが自動的に有効になります。）

ボリュームグループには、DA対応ドライブとDA非対応ドライブの両方を含めることができますが、この機能を使用するには、すべてのドライブがDA対応である必要があります。



 a| 
リソース プロビジョニング対応（EF300およびEF600のみ）
 a| 
このグループでResource Provisioningが利用可能かどうかを示します。Resource Provisioningは、EF300およびEF600ストレージアレイで利用可能な機能であり、バックグラウンドでの初期化プロセスなしでボリュームをすぐに使用できるようにします。



 a| 
シェルフ損失の保護
 a| 
シェルフ損失保護が利用可能かどうかを示します。シェルフ損失保護は、シェルフとの通信が完全に途絶した場合でも、ボリュームグループ内のボリューム上のデータへのアクセスを保証します。



 a| 
ドロワー損失の保護
 a| 
引き出し紛失保護機能が利用可能かどうかを示します。この機能は、引き出し付きのドライブシェルフを使用している場合にのみ提供されます。ドライブシェルフ内の単一の引き出しとの通信が完全に途絶した場合でも、引き出し紛失保護機能により、ボリュームグループ内のボリューム上のデータへのアクセスが保証されます。



 a| 
サポートされるボリューム ブロック サイズ（EF300およびEF600のみ）
 a| 
グループ内のボリュームに対して作成できるブロック サイズを示します。

** 512n - 512 バイト ネイティブ。
** 512e - 512 バイト エミュレーション。
** 4K -- 4,096 バイト。

メディア タイプ
 a|

** ハード ドライブ

ボリュームグループ内のすべてのドライブは、同じメディアタイプである必要があります（すべてSSD、またはすべてハードドライブ）。ボリュームグループには、異なるメディアタイプまたはインターフェースタイプを混在させることはできません。
