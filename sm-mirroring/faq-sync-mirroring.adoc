[[how-does-asynchronous-mirroring-differ-from-synchronous-mirroring]]
== 非同期ミラーリングと同期ミラーリングの違いは何ですか?

非同期ミラーリング機能が同期ミラーリング機能と本質的に違う点は、非同期ミラーリングは特定の時点におけるソース ボリュームの状態をキャプチャし、前回のイメージ キャプチャ以降に変更されたデータのみをコピーする点です。

同期ミラーリングでは、プライマリ ボリュームの状態がある時点でキャプチャされるのではなく、プライマリ ボリューム上で行われたすべての変更がセカンダリ ボリュームに反映されます。同期ミラーリングではプライマリ ボリュームに書き込みが行われるたびにセカンダリ ボリュームにも書き込みが行われるため、セカンダリ ボリュームはどの時点においてもプライマリ ボリュームと同一です。プライマリ ボリュームで行われた変更でセカンダリ ボリュームが更新されるまで、ホストは書き込みが成功したという確認応答を受信しません。

非同期ミラーリングでは、リモート ストレージ アレイとローカル ストレージ アレイは完全には同期されません。そのため、ローカル ストレージ アレイの損失によってアプリケーションをリモート ストレージ アレイに移行する必要がある場合、一部のトランザクションが失われる可能性があります。

ミラーリング機能の比較：

[cols="1a,1a"]
|===
| 非同期ミラーリング | 同期ミラーリング 


 a| 
*レプリケーション方法*



 a| 
* *ポイントインタイム*
+
ミラーリングはオンデマンドで、またはユーザ定義のスケジュールに従って自動的に行われます。スケジュールは分単位で定義できます。同期の最小間隔は10分です。


 a| 
* *連続*
+
ミラーリングは継続して自動的に実行され、ホストに書き込みがあるたびにデータがコピーされます。





 a| 
*予約容量*



 a| 
* *複数*
+
ミラー ペアごとにリザーブ容量ボリュームが1個必要です。


 a| 
* *シングル*
+
すべてのミラー ボリュームに対してリザーブ容量ボリュームが1個必要です。





 a| 
*コミュニケーション*



 a| 
* *iSCSI および Fibre Channel*
+
ストレージ アレイ間でiSCSIインターフェイスとFibre Channelインターフェイスをサポートします。


 a| 
* *ファイバチャネル*
+
ストレージ アレイ間でFibre Channelインターフェイスのみをサポートします。





 a| 
*距離*



 a| 
* *無制限*
+
ローカル ストレージ アレイとリモート ストレージ アレイの間のサポートされる距離は事実上無制限です。通常は、ネットワークとチャネル拡張テクノロジの機能によってのみ距離が制限されます。


 a| 
* *制限付き*
+
レイテンシおよびアプリケーション パフォーマンスの要件を満たすために、通常はローカル ストレージ アレイから約10km（6.2マイル）以内とする必要があります。

[[synchronous-mirroring-why-dont-i-see-all-my-volumes]]
== 同期ミラーリング - ボリュームが一部表示されないのはなぜですか?

ミラー ペアのプライマリ ボリュームを選択すると、対応するすべてのボリュームのリストが表示されます。

使用できないボリュームはリストに表示されません。次のいずれかの理由で、ボリュームが対象外になっている可能性があります。

* ボリュームが標準以外のボリューム（Snapshotボリューム、シン ボリュームなど）である。
* 最適状態でない。
* すでにミラー関係に参加している。




[[synchronous-mirroring-why-dont-i-see-all-the-volumes-on-the-remote-storage-array]]
== 同期ミラーリング - リモート ストレージ アレイのボリュームが一部表示されないのはなぜですか?

リモート ストレージ アレイ上のセカンダリ ボリュームを選択すると、そのミラー ペアに対応するすべてのボリュームのリストが表示されます。

使用に適さないボリュームはリストには表示されません。次のいずれかの理由で、ボリュームが対象外になっている可能性があります。

* ボリュームが標準以外のボリューム（Snapshotボリューム、シン ボリュームなど）である。
* 最適状態でない。
* すでにミラー関係に参加している。
* Data Assurance（DA）を使用する場合、プライマリ ボリュームとセカンダリ ボリュームでDA設定を同じにする必要があります。
+
** プライマリ ボリュームがDA対応の場合、セカンダリ ボリュームもDA対応である必要があります。
** プライマリ ボリュームがDA有効になっていない場合、セカンダリ ボリュームもDA有効になっていてはいけません。






[[synchronous-mirroring-what-do-i-need-to-know-before-creating-a-mirrored-pair]]
== 同期ミラーリング - ミラー ペアを作成するときは、どのような点に注意する必要がありますか?

ミラーペアは SANtricity Unified Manager インターフェイスで設定し、SANtricity System Manager でペアを管理します。

ミラー ペアを作成する際は、次のガイドラインに従ってください。

* 2つのストレージ アレイが必要です。
* 各ストレージ アレイに2台のコントローラが必要です。
* プライマリ アレイとセカンダリ アレイ内の各コントローラにイーサネット管理ポートが設定されていて、各コントローラがネットワークに接続されている必要があります。
* ローカルストレージアレイとリモートストレージアレイは、Fibre Channelファブリックを介して接続されています。
* ストレージ アレイに必要なファームウェアの最小バージョンは7.84です。（ストレージ アレイごとに異なるバージョンのOSを実行できます）。
* ローカルとリモートのストレージ アレイのパスワードを確認しておく必要があります。
* リモート ストレージ アレイにセカンダリ ボリュームを作成するための十分な空き容量（ミラーリングするプライマリ ボリュームと同等以上）が必要です。
* Web Services ProxyとUnified Managerをインストールしました。ミラーリングされたペアは、Unified Managerのインターフェースで設定されます。
* Unified Managerで2つのストレージアレイが検出されます。




[[what-impact-does-synchronization-priority-have-on-synchronization-rates]]
== 同期の優先順位は同期速度にどのような影響を与えますか？

同期優先度は、システム パフォーマンスに対して同期アクティビティにどれだけの処理時間を割り当てるかを定義します。

プライマリ ボリュームのコントローラ所有者が、この処理をバックグラウンドで実行します。同時に、コントローラ所有者はプライマリ ボリュームへのローカルI/O書き込みと、セカンダリ ボリュームへの関連するリモート書き込みを処理します。再同期はコントローラの処理リソースをI/Oアクティビティから転用するため、ホスト アプリケーションのパフォーマンスに影響を与える可能性があります。

同期の優先順位付けにかかる時間や、同期の優先順位付けがシステムパフォーマンスに及ぼす影響を判断する際は、以下のガイドラインを参考にしてください。

.同期優先度について
[%collapsible]
====
指定できる優先度は次のとおりです。

* 最低
* 低
* 中
* 高
* 最高


最低ではシステム パフォーマンスが優先されますが、再同期に時間がかかります。最高では再同期が優先されますが、システム パフォーマンスが低下する可能性があります。

[[why-is-it-recommended-to-use-a-manual-synchronization-policy]]
== 手動同期ポリシーの使用が推奨されるのはなぜですか?

手動での再同期を推奨します。なぜなら、手動での再同期を行うことで、データ復旧の可能性を最大限に高める方法で再同期プロセスを管理できるからです。

自動再同期ポリシーを使用し、再同期中に断続的な通信問題が発生した場合、セカンダリ ボリュームのデータが一時的に破損している可能性があります。再同期が完了すると、データが修正されます。
