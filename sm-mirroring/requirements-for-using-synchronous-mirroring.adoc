= SANtricity ソフトウェアで同期ミラーリングを使用するための要件
:allow-uri-read: 
:experimental: 
:icons: font
:imagesdir: ../media/


[role="lead"]
同期ミラーリングを使用する場合は、次の要件に注意してください。



[[unified-manager]]
== Unified Manager

2つのアレイ間のミラーリングを有効にして設定するには、Unified Managerインターフェイスを使用する必要があります。Unified Managerは、Web Services Proxyとともにホスト システムにインストールされます。

* Web Services Proxyサービスが実行されている必要があります。
* Unified ManagerがHTTPS接続経由でローカル ホストで実行されている必要があります。
* Unified Managerは、ストレージアレイに対して有効なSSL証明書を表示している必要があります。Unified Managerを使用して、メニューの「証明書」[証明書管理]に移動することで、自己署名証明書を受け入れるか、独自のセキュリティ証明書をインストールできます。




[[storage-arrays]]
== ストレージ アレイ

[NOTE]
====
EF300/EF300C または EF600/EF600C ストレージ アレイでは、同期ミラーリングは利用できません。

====
* 2つのストレージ アレイが必要です。
* 各ストレージ アレイに2台のコントローラが必要です。
* Unified Managerで2つのストレージ アレイが検出されている必要があります。
* プライマリ アレイとセカンダリ アレイ内の各コントローラにイーサネット管理ポートが設定されていて、各コントローラがネットワークに接続されている必要があります。
* ストレージ アレイに必要なファームウェアの最小バージョンは7.84です。（ストレージ アレイごとに異なるバージョンのOSを実行できます）。
* ローカルとリモートのストレージ アレイのパスワードを確認しておく必要があります。
* リモート ストレージ アレイにセカンダリ ボリュームを作成するための十分な空き容量（ミラーリングするプライマリ ボリュームと同等以上）が必要です。
* ローカルストレージアレイとリモートストレージアレイは、Fibre Channelファブリックを介して接続されています。




[[supported-connections]]
== サポートされる接続

同期ミラーリングのための通信は、Fibre Channel（FC）ホスト ポートを備えたコントローラでのみサポートされています。

同期ミラーリングでは、ローカルストレージアレイとリモートストレージアレイの両方において、各コントローラ上で最も番号の大きいホストポートが使用されます。コントローラホストバスアダプタ（HBA）のホストポート4は、通常、ミラーデータの送信用に予約されています。



[[mirrored-volume-candidates]]
== ミラー ボリュームの候補

* 同期ミラーリングされたペアのプライマリ ボリュームとセカンダリ ボリュームでは、RAID レベル、キャッシュ パラメータ、セグメント サイズが異なる場合があります。
* 同期ミラー ペアのプライマリ ボリュームとセカンダリ ボリュームは、標準ボリュームである必要があります。シン ボリュームやSnapshotボリュームは使用できません。
* セカンダリ ボリュームには、プライマリ ボリュームと同等以上のサイズが必要です。
* スナップショットを関連付けることができるのはプライマリ ボリュームのみであり、また、ボリューム コピー操作におけるソース ボリュームまたはターゲット ボリュームとなることができるのもプライマリ ボリュームのみです。
* ボリュームに設定できるミラー関係は1つだけです。
* 特定のストレージ アレイでサポートされるボリュームの数には制限があります。お使いのストレージ アレイに設定されているボリュームの数がサポートされている制限よりも少ないことを確認してください。同期ミラーリングがアクティブな場合は、作成済みの2個のリザーブ容量ボリュームがボリュームの制限に含まれます。




[[reserved-capacity]]
== リザーブ容量

* プライマリ ボリュームとセカンダリ ボリュームには、コントローラのリセットやその他の一時的な中断から復旧するための書き込み情報をログ記録するために、予約済み容量が必要です。
* 同期ミラーリングが有効になると、予約容量ボリュームが自動的に作成されます。ミラー ペアのプライマリ ボリュームとセカンダリ ボリュームの両方で予約容量が必要になるため、同期ミラー関係に参加している両方のストレージ アレイに十分な空き容量があることを確認する必要があります。




[[drive-security-feature]]
== ドライブ セキュリティ機能

* セキュリティ対応ドライブを使用する場合、プライマリ ボリュームとセカンダリ ボリュームのセキュリティ設定に互換性がある必要があります。この制限は強制的には適用されないため、自分で確認する必要があります。
* セキュリティ対応ドライブを使用する場合、プライマリ ボリュームとセカンダリ ボリュームで同じタイプのドライブを使用する必要があります。この制限は強制的には適用されないため、自分で確認する必要があります。
+
** プライマリ ボリュームがフルディスク暗号化（FDE）ドライブを使用している場合、セカンダリ ボリュームはFDEドライブを使用する必要があります。
** プライマリ ボリュームが連邦情報処理規格140-2（FIPS）検証済みドライブを使用している場合、セカンダリ ボリュームはFIPS 140-2検証済みドライブを使用する必要があります。


* Data Assurance（DA）を使用する場合、プライマリ ボリュームとセカンダリ ボリュームでDA設定を同じにする必要があります。
