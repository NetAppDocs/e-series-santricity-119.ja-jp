[[what-do-i-need-to-know-before-creating-a-mirror-consistency-group]]
== ミラー整合性グループを作成するときは、どのような点に注意する必要がありますか?

ミラー整合性グループを作成する際は、次のガイドラインに従ってください。

Unified Managerの以下の要件を満たしてください：

* Web Services Proxyサービスが実行されている必要があります。
* Unified ManagerがHTTPS接続経由でローカル ホストで実行されている必要があります。
* Unified Managerは、ストレージアレイに対して有効なSSL証明書を表示している必要があります。Unified Managerを使用して、メニューの「証明書」[証明書管理]に移動することで、自己署名証明書を受け入れるか、独自のセキュリティ証明書をインストールできます。


また、ストレージ アレイに関する次の要件を満たしていることも確認してください。

* Unified Managerで2つのストレージ アレイが検出されている必要があります。
* 各ストレージ アレイに2台のコントローラが必要です。
* プライマリ アレイとセカンダリ アレイ内の各コントローラにイーサネット管理ポートが設定されていて、各コントローラがネットワークに接続されている必要があります。
* ストレージ アレイに必要なファームウェアの最小バージョンは7.84です。（ストレージ アレイごとに異なるバージョンのOSを実行できます）。
* ローカルとリモートのストレージ アレイのパスワードを確認しておく必要があります。
* ローカルとリモートのストレージ アレイをFibre ChannelファブリックまたはiSCSIインターフェイスを介して接続します。


[NOTE]
====
EF600/EF600CまたはEF300/EF300Cストレージ システムでは、同期ミラーリングは利用できません。

====


[[what-do-i-need-to-know-before-creating-a-mirrored-pair]]
== ミラー ペアを作成するときは、どのような点に注意する必要がありますか?

ミラー ペアを作成する際は、次のガイドラインに従ってください。

* 2つのストレージ アレイが必要です。
* 各ストレージ アレイに2台のコントローラが必要です。
* Unified Managerで2つのストレージ アレイが検出されている必要があります。
* プライマリ アレイとセカンダリ アレイ内の各コントローラにイーサネット管理ポートが設定されていて、各コントローラがネットワークに接続されている必要があります。
* ストレージ アレイに必要なファームウェアの最小バージョンは7.84です。（ストレージ アレイごとに異なるバージョンのOSを実行できます）。
* ローカルとリモートのストレージ アレイのパスワードを確認しておく必要があります。
* リモート ストレージ アレイにセカンダリ ボリュームを作成するための十分な空き容量（ミラーリングするプライマリ ボリュームと同等以上）が必要です。
* 非同期ミラーリングはFibre Channel（FC）またはiSCSIホスト ポートを備えたコントローラでサポートされますが、同期ミラーリングはFCホスト ポートを備えたコントローラでのみサポートされます。


[NOTE]
====
EF600/EF600CまたはEF300/EF300Cストレージ システムでは、同期ミラーリングは利用できません。

====


[[why-would-i-change-this-percentage]]
== この割合を変更するのはどのような場合ですか?

非同期ミラーリング処理用のリザーブ容量は、一般にベース ボリュームの20%です。通常はこの容量で十分です。

必要な容量は、ベースボリュームへのI/O書き込みの頻度とサイズ、およびストレージオブジェクトのコピーサービス操作を使用する予定期間によって異なります。一般的に、以下の条件のいずれか、または両方が当てはまる場合は、予約容量の割合を高く設定してください：

* 特定のストレージオブジェクトのコピーサービス操作の寿命が非常に長い場合。
* 大量のI/Oアクティビティにより、ベースボリューム上のデータブロックの大部分が変更される場合。過去のパフォーマンスデータやその他のオペレーティングシステムユーティリティを使用して、ベースボリュームへの典型的なI/Oアクティビティを把握してください。




[[why-do-i-see-more-than-one-reserved-capacity-candidate]]
== リザーブ容量の候補が複数表示されるのはなぜですか?

プールまたはボリューム グループ内にストレージ オブジェクトに対して選択した容量の割合（%）を満たす複数のボリュームがある場合は、複数の候補が表示されます。

ベース ボリューム上でコピー サービス処理用にリザーブする物理ドライブ スペースの割合を変更すると、推奨される候補の一覧が更新されます。選択内容に基づいて、最適な候補が表示されます。



[[why-dont-i-see-all-my-volumes]]
== ボリュームが一部表示されないのはなぜですか?

ミラー ペアのプライマリ ボリュームを選択すると、対応するすべてのボリュームのリストが表示されます。

使用できないボリュームはリストに表示されません。次のいずれかの理由で、ボリュームが対象外になっている可能性があります。

* 最適状態でない。
* すでにミラー関係に参加している。
* 同期ミラーリングの場合、ミラー ペアのプライマリ ボリュームとセカンダリ ボリュームは標準ボリュームである必要があります。シン ボリュームやSnapshotボリュームは使用できません。
* 非同期ミラーリングの場合は、シン ボリュームで自動拡張が有効になっている必要があります。



NOTE: EF600およびEF300のコントローラでは、非同期ミラー ペアのプライマリ ボリュームとセカンダリ ボリュームで、プロトコル、トレイ レベル、セグメント サイズ、セキュリティ タイプ、およびRAIDレベルが同じである必要があります。そうでない非同期ミラー ペアは、使用可能なボリュームのリストに表示されません。



[[why-dont-i-see-all-the-volumes-on-the-remote-storage-array]]
== リモート ストレージ アレイのボリュームが一部表示されないのはなぜですか?

リモート ストレージ アレイ上のセカンダリ ボリュームを選択すると、そのミラー ペアに対応するすべてのボリュームのリストが表示されます。

使用に適さないボリュームはリストには表示されません。次のいずれかに該当するボリュームは対応しない場合があります。

* 標準以外のボリューム（Snapshotボリュームなど）である。
* 最適状態でない。
* すでにミラー関係に参加している。
* （非同期ミラーリングの場合）シン ボリューム属性が、プライマリ ボリュームとセカンダリ ボリュームで一致しない。
* Data Assurance（DA）を使用する場合、プライマリ ボリュームとセカンダリ ボリュームでDA設定を同じにする必要があります。
+
** プライマリ ボリュームがDA対応の場合、セカンダリ ボリュームもDA対応である必要があります。
** プライマリ ボリュームがDA有効になっていない場合、セカンダリ ボリュームもDA有効になっていてはいけません。


* 非同期ミラーリングの場合、プライマリ ボリュームとセカンダリ ボリュームでドライブ セキュリティ機能が同じである必要があります。
+
** プライマリ ボリュームがFIPS対応の場合、セカンダリ ボリュームもFIPS対応である必要があります。
** プライマリ ボリュームがFDE対応の場合、セカンダリ ボリュームもFDE対応である必要があります。
** プライマリ ボリュームがDrive Securityを使用していない場合は、セカンダリ ボリュームもDrive Securityを使用してはいけません。






[[what-impact-does-synchronization-priority-have-on-synchronization-rates]]
== 同期の優先順位は同期速度にどのような影響を与えますか？

同期優先度は、システム パフォーマンスに対して同期アクティビティにどれだけの処理時間を割り当てるかを定義します。

プライマリ ボリュームのコントローラ所有者が、この処理をバックグラウンドで実行します。同時に、コントローラ所有者はプライマリ ボリュームへのローカルI/O書き込みと、セカンダリ ボリュームへの関連するリモート書き込みを処理します。再同期はコントローラの処理リソースをI/Oアクティビティから転用するため、ホスト アプリケーションのパフォーマンスに影響を与える可能性があります。

同期の優先順位付けにかかる時間や、同期の優先順位付けがシステムパフォーマンスに及ぼす影響を判断する際は、以下のガイドラインを参考にしてください。

指定できる優先度は次のとおりです。

* 最低
* 低
* 中
* 高
* 最高


最低ではシステム パフォーマンスが優先されますが、再同期に時間がかかります。最高では再同期が優先されますが、システム パフォーマンスが低下する可能性があります。

[[why-is-it-recommended-to-use-a-manual-synchronization-policy]]
== 手動同期ポリシーの使用が推奨されるのはなぜですか?

手動での再同期を推奨します。なぜなら、手動での再同期を行うことで、データ復旧の可能性を最大限に高める方法で再同期プロセスを管理できるからです。

自動再同期ポリシーを使用し、再同期中に断続的な通信問題が発生した場合、セカンダリ ボリュームのデータが一時的に破損している可能性があります。再同期が完了すると、データが修正されます。
