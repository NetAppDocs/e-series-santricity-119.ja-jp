= SANtricity System Managerのイベントログを使用してイベントを表示します
:allow-uri-read: 
:experimental: 
:icons: font
:imagesdir: ../media/


[role="lead"]
ストレージ アレイで発生したイベントの履歴レコードを提供するイベント ログを表示できます。

.手順
. メニューの「Support」→「Event Log」を選択してください。
+
イベント ログ ページが表示されます。

+
.ページの詳細
[%collapsible]
====
[cols="25h,~"]
|===
| 項目 | 概要 


 a| 
[すべて表示]フィールド
 a| 
すべてのイベントを表示するか、重大 / 警告イベントだけを表示するかを切り替えます。



 a| 
[フィルタ]フィールド
 a| 
イベントをフィルタします。たとえば、特定のコンポーネントに関連するイベントや特定のイベントだけを表示する場合に役立ちます。



 a| 
[列を選択]アイコン
 a| 
表示する他の列を選択できます。他の列には、イベントに関する追加情報が表示されます。



 a| 
チェック ボックス
 a| 
保存するイベントを選択できます。テーブルのヘッダーにあるチェック ボックスをオンにすると、すべてのイベントが選択されます。



 a| 
[日付 / 時刻]列
 a| 
コントローラ クロックに準じたイベントの日付と時刻のタイムスタンプ。


NOTE: イベント ログでは、最初にシーケンス番号に基づいてイベントをソートします。通常、このシーケンスは日付と時刻に対応します。ただし、ストレージ アレイ内の2つのコントローラ クロックは同期されない可能性があります。この場合、イベント ログに表示されるイベントと日時に不整合が生じる可能性があります。



 a| 
[優先度]列
 a| 
優先度の値は次のとおりです。

** *Critical* -- ストレージアレイに問題が発生しています。ただし、すぐに対処すれば、データへのアクセスが失われるのを防ぐことができます。Criticalイベントは、アラート通知に使用されます。すべてのCriticalイベントは、ネットワーク管理クライアント（SNMPトラップ経由）または設定したEメール受信者に送信されます。
** *警告* -- エラーが発生し、ストレージ アレイのパフォーマンスと、別のエラーからの復旧能力が低下しました。
** *情報* -- ストレージ アレイに関連する重要度の低い情報。




 a| 
[コンポーネント タイプ]列
 a| 
イベントの影響を受けるコンポーネント。ハードウェア（ドライブ、コントローラなど）またはソフトウェア（コントローラ ファームウェア）のどちらかです。



 a| 
[コンポーネントの場所]列
 a| 
ストレージ アレイ内のコンポーネントの物理的な場所。



 a| 
[説明]列
 a| 
イベントの説明。

*例* -- `Drive write failure - retries exhausted`



 a| 
[シーケンス番号]列
 a| 
ストレージアレイ内の特定のログエントリを一意に識別する64ビットの数値。この数値は、新しいイベントログエントリが追加されるたびに1ずつ増加します。この情報を表示するには、*列の選択*アイコンをクリックします。



 a| 
[イベント タイプ]列
 a| 
記録されたイベントの種類ごとに識別する4桁の数字。この情報を表示するには、*列の選択*アイコンをクリックします。



 a| 
[イベント固有のコード]列
 a| 
この情報はテクニカルサポートによって使用されます。この情報を表示するには、*列の選択*アイコンをクリックします。



 a| 
[イベント カテゴリ]列
 a| 
** **障害** – ストレージアレイ内のコンポーネントに障害が発生しました。たとえば、ドライブ障害またはバッテリー障害。
** **状態変化** – ストレージ アレイの要素の状態が変化したこと。たとえば、ボリュームが最適ステータスに移行した場合や、コントローラがオフライン ステータスに移行した場合などです。
** **内部** – ユーザー操作を必要としない内部コントローラ操作（コントローラが一日の開始処理を完了した場合など）。
** **コマンド** – ストレージアレイに対して発行されたコマンド（例：ホットスペアが割り当てられた）。
** **エラー** – ストレージアレイでエラー状態が検出されました。たとえば、コントローラがキャッシュの同期とパージを実行できない、またはストレージアレイで冗長性エラーが検出された場合などです。
** **一般** – 他のどのカテゴリーにもうまく当てはまらないイベント全般。この情報を表示するには、**列の選択**アイコンをクリックしてください。




 a| 
[ログ元]列
 a| 
イベントをログに記録したコントローラの名前。この情報を表示するには、**列の選択**アイコンをクリックします。

|===
====
. ストレージアレイから新しいイベントを取得するには、**更新**をクリックします。
+
イベントが記録され、イベントログページに表示されるまでには数分かかる場合があります。

. イベント ログをファイルに保存するには、次の手順を実行します。
+
.. 保存する各イベントの横にあるチェック ボックスをオンにします。
.. *保存*をクリックします。
+
ファイルは、ブラウザのダウンロードフォルダに次の名前で保存されます `major-event-log-timestamp.log`。



. イベント ログからイベントをクリアするには、次の手順を実行します。
+
イベント ログに約8,000個のイベントが格納されると、1つのイベントが新しいイベントに置き換えられます。イベントを保持する場合は、そのイベントを保存してイベント ログからクリアできます。

+
.. 最初に、イベント ログを保存します。
.. *すべてクリア*をクリックし、操作を実行することを確認します。
